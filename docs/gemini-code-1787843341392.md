# Contexto General: MVP Sistema de Tickets - Módulo 3 (M3)

## Objetivo
Desarrollar el Módulo 3 (M3) de un sistema de tickets (Kanban). Este módulo consiste en un único componente Modal que cumple una doble función: mostrar el detalle de un ticket ("Ver Más" / Solo lectura) y permitir su edición mediante un formulario ("Modo Edición").

## Stack Tecnológico
- React (con JavaScript estándar, sin TypeScript).
- React-Bootstrap (para componentes visuales y modales, prohibido usar CSS custom si Bootstrap lo puede resolver).
- Entorno: Vite.

## Arquitectura y Componentes
Para asegurar la modularidad, el M3 debe dividirse en los siguientes archivos/componentes:

1. **`ticketStates.js` (Constants):** Un diccionario/objeto con los estados permitidos del ticket (PENDIENTE, EN_PROGRESO, TERMINADO).
2. **`TicketDetalle.jsx`:** Componente de solo lectura. Muestra el título, la descripción (como texto) y el estado (como Badge de Bootstrap).
3. **`TicketForm.jsx`:** Componente de formulario controlado. Renderiza los inputs para Título (text), Descripción (textarea) y Estado (select). 
4. **`ModalTicket.jsx`:** El componente principal y contenedor. Gestiona el renderizado condicional entre `TicketDetalle` y `TicketForm`.

## Reglas de Estado y Props (Importante)
El componente `ModalTicket` es un **componente controlado** desde el exterior (M1). 
Debe recibir las siguientes props:
- `ticket`: Objeto con la información del ticket a mostrar/editar.
- `isOpen`: Booleano que controla la visibilidad del modal.
- `onClose`: Función para solicitarle al padre que cierre el modal.
- `onTicketUpdated`: Función para enviarle al padre el ticket con los datos actualizados tras guardar.

Internamente, `ModalTicket` debe manejar un estado local:
- `isEditing` (boolean, default: false): Determina qué sub-componente renderizar (`TicketDetalle` o `TicketForm`).

## Flujo de UX / Comportamiento de Botones

**Estado 1: Modo Lectura (`isEditing === false`)**
- Se renderiza `TicketDetalle`.
- Footer: 
  - Botón "Cerrar" (Secundario) -> Ejecuta `onClose()`.
  - Botón "Editar" (Primario) -> Cambia el estado `isEditing` a `true`.

**Estado 2: Modo Edición (`isEditing === true`)**
- Se renderiza `TicketForm`.
- Footer:
  - Botón "Cancelar" (Secundario) -> Cambia el estado `isEditing` a `false` (NO cierra el modal, vuelve a modo lectura descartando cambios no guardados).
  - Botón "Guardar Cambios" (Primario, de tipo submit asociado al form) -> Debe prender un estado de carga (bloquear botones y mostrar un spinner de Bootstrap), simular una llamada asíncrona exitosa, ejecutar `onTicketUpdated(ticketModificado)`, resetear `isEditing` a `false` y ejecutar `onClose()`.
